v2.5 is this fork's first release with the Clash (mihomo) proxy backend for the
ZTE U60 Pro (MU5250) on CN B31 firmware: one Proxy page for WireGuard and Clash,
a fix for B31's clock, one-tap diagnostics, core and geo data updates on the
modem, proxy controls on the touchscreen and a hardened agent HTTP server.
Agent, dashboard and installer are versioned 2.5.0.

### Proxy page

- WireGuard and Clash share one Proxy page. Choose Off, WireGuard or Clash at the
  top; a switch stops the running backend and starts the chosen one in one
  transaction, holding LAN traffic meanwhile, and restores the previous backend
  if the new one fails. Each backend's settings stay below.

### Clash

- **Clock.** B31 keeps Beijing time in its system clock as if it were UTC, 8 hours
  ahead, so VMess, Shadowsocks 2022 and some REALITY servers refused every node
  (`get delay: all proxies timeout`). The generated profile runs the core's own NTP
  client (ntp.aliyun.com by address, every 5 minutes, `write-to-system: false`);
  the system clock is left alone.
- **Root certificates.** The pinned core `flclash-d0c8d44-openui-ca20260925` embeds
  Mozilla's root certificates (curl's 2026-09-25 bundle); earlier builds had none.
- **Diagnostics.** One tap, on the Proxy page or the touchscreen, checks the clock,
  the core, DNS, the selected nodes, fetches through the core, which devices are
  proxied, routing and the firewall hooks, and names the likely cause when sites
  that need the proxy do not open. `scripts/device/diagnose-clash.sh` runs a
  read-only version over SSH.
- **Core and geo data.** Check for and install official MetaCubeX mihomo releases
  on the modem (digest from GitHub, arm64, `-v` and `-t` checks, automatic rollback
  if the new core does not start), upload your own build, roll back, and update the
  geo databases against their published checksums.
- **Subscriptions.** Every download (add, URL change, manual or automatic refresh)
  is checked by the core before it can replace the stored profile; a rejected
  profile reports the core's own error.

### Touchscreen (DevUI)

- Default menu: Overview, Proxy, WireGuard, Clash. Switch the backend, change the
  Clash mode, browse groups and nodes, select nodes and run delay tests, use or
  refresh subscriptions, check, update or roll back the core, update geo data and
  run diagnostics. Subscriptions are still added on the web page: the screen has
  no text entry.

### Agent HTTP

- tiny_http 0.12 is vendored with limits (`vendor/tiny_http/OPENUI-PATCH.md`): a
  request claiming a huge body no longer aborts the agent, stalled or trickled
  bodies cannot tie up the API's worker threads, request lines, header counts and
  connection time are bounded, and HTTP/2 request lines get 505 instead of hanging
  a thread.

**Do not use the desktop installers with this fork.** They download packages from
upstream OpenUI (`dklasens/MU5250-OpenUI`) and would replace the WireGuard, Clash
and touchscreen additions. Geo data is not attached; prepare it with
`python3 scripts/prepare-geodata.py`.

### Deploy

From a checkout of this tag, pass the downloaded files to
`scripts/deploy-components.py` (`--agent`, `--dashboard`, `--screen`, `--mihomo`,
`--mihomo-geodata`) with `--dry-run` first, then without it; see the README and
[docs/CLASH.md](../CLASH.md). Deploy the agent and the screen program together.
Restore the stock screen before replacing the screen program, then run
`scripts/verify-screen.py`; the touchscreen entry stays disabled until it passes.

### Validation

- CI: Rust, web, Python and installer checks; the core is built, smoke-tested
  under qemu and delay-tested through a node with only its built-in roots.
- End-to-end on a simulated U60 (the real x86_64 agent and mihomo with iptables,
  policy routing and TUN): 11 scenarios and 4 extra probes passed; see
  docs/PLAN.md.
- Not yet run on a real modem: the clock fix, the touchscreen program, core
  replacement and rollback on arm64, and the firmware's own firewall rules. Run
  `verify-screen.py` and the Clash diagnostics after deploying.

v2.6 adds eSIM management to this fork for the ZTE U60 Pro (MU5250) on CN B31
firmware. You can switch, download, rename and delete the profiles on a removable
eUICC card in the SIM tray from the web page, as EasyEUICC does on Android, and
switch profiles from the touchscreen. Agent, dashboard and installer are versioned
2.6.0.

### eSIM

- **Cards.** Removable eUICC cards such as 9eSIM, 5ber and eSTK.me. An ordinary
  SIM card is recognised and reported. A built-in ZTE eSIM, on units that have
  one, is not supported.
- **Web page (Modem → eSIM).**
  - Card details: EID, SGP.22 version, eUICC firmware, free space and default
    SM-DP+.
  - Profiles: the list, switch, disable, rename, and delete (type the name to
    confirm).
  - Downloads from an `LPA:1$…` activation code, a QR image (a file or a pasted
    screenshot), or the SM-DP+ address and matching ID. Confirmation code and IMEI
    are optional fields.
  - Notifications to the SM-DP+ are sent at once, as EasyEUICC does by default.
    Any that fail stay in the list, where you can send or remove them.
- **Touchscreen.** An eSIM page lists the profiles by name and last four ICCID
  digits, and switches to one after you confirm. To show it, add eSIM to the
  screen's menu features on the DevUI page; the default menu is unchanged.
- **Switching.** OpenUI enables the profile, then the modem reads the card again:
  radio to low power, SIM power off and on, radio online. This sequence was
  verified on B31 by SadykovIV/ZTE_U60Pro. OpenUI then waits for the modem, the
  USIM and the firmware to report the new profile.
  - If the firmware keeps the previous profile, the web page and the screen offer
    a restart. Nothing restarts on its own.
  - A switch takes the mobile connection down for 10–30 s. Switching to a profile
    without data during a remote session loses access.
- **How it works.** The agent runs lpac for each command.
  - Card commands go to the modem's QMI UIM service over QRTR, on a logical
    channel to the ISD-R. No AT commands are used and no libqmi is needed on the
    device.
  - SM-DP+ requests go through curl, HTTPS only. Certificates are checked against
    the GSMA CI roots that SM-DP+ certificates chain to and against the system
    store. Requests go through Clash while it runs.

  See [docs/ESIM.md](../ESIM.md).

### lpac

- lpac v2.3.0 (`v2.3.0-openui1`): a static aarch64 build with only the stdio APDU
  and HTTP drivers. Later lpac versions load drivers with `dlopen()`, which a
  static binary cannot do.
- It is built from the SHA-256-pinned source archive and the nine patches in
  `scripts/lpac-patches/`:
  - seven upstream fixes, since the v2.3.0 stdio driver could not work at all;
  - a fix for a crash after a failed command, which left the card's logical
    channel open;
  - faster reading of large replies.
- `scripts/prepare-lpac.py` builds it with Zig 0.14.1 and checks the output
  against a pinned sha256. The release workflow builds it the same way and runs
  it under qemu.

`python3 scripts/prepare-geodata.py`.

### Deploy

From a checkout of this tag, pass the downloaded files to
`scripts/deploy-components.py` (`--agent`, `--dashboard`, `--screen`, `--lpac`,
`--mihomo`, `--mihomo-geodata`). Run it with `--dry-run` first, then without it.
See the README, [docs/CLASH.md](../CLASH.md) and [docs/ESIM.md](../ESIM.md).

- `--lpac` checks that `lpac` is the pinned build, runs `lpac version` from a
  staged copy, and keeps lpac in the rollback snapshot. Without lpac, the eSIM tab
  says that it is not installed.
- Deploy the agent and the screen program together.
- Restore the stock screen before replacing the screen program, then run
  `scripts/verify-screen.py`. The touchscreen entry stays disabled until it
  passes.

### Validation

- **CI.** Rust, web, Python and installer checks. lpac is built from its pinned
  sources, matched against its pinned sha256, and run under qemu: request order,
  the error path closing its channel, and a 2 MB reply.
- **End-to-end on a simulated U60.** All passed; see docs/PLAN.md.
  - The 11 scenarios and 4 extra probes from v2.5.
  - An eSIM scenario with the real x86_64 agent and lpac against a simulated
    modem and eUICC (over a QMI transport that exists only in debug builds) and an
    HTTPS SM-DP+. It covers reading, renaming, switching and the order of the
    radio and SIM power steps, a firmware that does not follow, `catBusy`,
    deleting, downloads (accepted, refused, with a confirmation code, with a
    duplicate ICCID), notifications, an ordinary SIM and an empty tray. No logical
    channel was left open.
  - The eSIM tab in a browser.
- **Not yet run on a real modem.**
  - New in v2.6: QRTR access to the UIM service under B31 firmware, the switch
    sequence and whether the firmware takes up a new profile without a restart,
    and downloads from real SM-DP+ servers. With an ordinary SIM in the tray,
    **Read the card** on Modem → eSIM should report an ordinary SIM card; that
    confirms QRTR access.
  - Carried over from v2.5: the clock fix, the touchscreen program, core
    replacement and rollback on arm64, and the firmware's own firewall rules.
